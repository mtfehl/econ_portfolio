Problem Set 2: Population & Marketplaces

Downloading and manipulating geospatial data to visualize populations, locations, and distances.
Author

Michael Fehl, Joan Costa, Francesco Zucca and Xènia Alemany (Group A)

Published

February 2, 2026

Part 1: World Population

Goals

  • Q1. Combine the world shape world with population (point) data and with ports & airports data.

  • Q2. Create maps & histograms regarding country-level population and average distances to nearest port/airport, segmented by continent.

Q1.1: Combining Datasets

Goal : Combine the world shape world with:

  • Population (point) data (do not use rasters!)
  • Ports, airports, etc.

Data

Data source

The data comes from two different sources, the spData library (which contains the “world” shapefile) and Natural Earth (Data Source). Specifically, from Natural Earth we download:

  • Populated Places dataset
  • Airports dataset
  • Ports dataset

Identifying the country for cities, airports, and ports

We need to identify the country and continent for every city, airport, and port. To do so, we will create an auxiliary dataset with only the country, continent, and geom columns of the world dataset, and then merge them based on their spatial information.

Our operation generated a lot of NA’s, especially in the airport and port datasets. This probably happens because some coastal locations are mapped slightly outside the country borders. Therefore, when using st_intersect, they don’t intersect with any country in the world dataset, generating NA’s.

To fix this, we will undo the last step and try again using a 10km buffer.

Show the code 
# Reverting to the original datasets
sf.airports <- sf.airports %>%
  select(- country, - continent)

sf.ports <- sf.ports %>%
  select(- country, - continent)

# Adding the country and continent columns to the datasets
sf.airports <- st_join(sf.airports, sf.world.aux, join = st_is_within_distance, dist = 10000)
sf.airports <- sf.airports %>%
  arrange(country)
mean(is.na(sf.airports$country)) * 100
[1] 7.359307
Show the code 
sf.ports <- st_join(sf.ports, sf.world.aux, join = st_is_within_distance, dist = 10000)
sf.ports <- sf.ports %>%
  arrange(country)
mean(is.na(sf.ports$country)) * 100
[1] 10.05435

This buffer fixed a lot of the missing values. However, this operation may not be totally accurate. For example, since some small islands are missing from our world map, a port may be assigned to the wrong country if it is withing 10km of its borders. Also, ports on islands that are further than 10 km away from the coastline are still not detected.

Q1.2: World Map & Histograms

Produce:

  • Map of total population by country
  • Histogram of country population distribution by continent
  • Histogram of (country-level) average distances between locations and ports or airports by continent. If there are too many locations and/or airports, filter the top 20 of them.

For ease of use and code tidiness, we will use the unmerged datasets.

Map of total population by country

To visualize population distribution, we will combine the world dataset with the cities dataset. First, we will plot the countries, using a color gradient to show their total population. Then, we will overlay the cities, grouping them into seven size categories to highlight population concentration.

Classification of Cities

OECD classifies urban areas as:

  • large metropolitan areas if they have a population of 1.5 million or more;
  • metropolitan areas if their population is between 500 000 and 1.5 * million;
  • medium-size urban areas if their population is between 200 000 and 500 000; and,
  • small urban areas if their population is between 50 000 and 200 000.

We will also add two more categories:

  • Megacities (population greater than 10M)
  • Towns (population from 5k to 50k)
  • Villages (population lower than 5k)

Our categories are:

  • Very low (< 5k population)
  • Low (5k to 50k population)
  • Medium-Low (50k to 200k population)
  • Medium (200k to 500k population)
  • Medium-High (500k to 1.5M population)
  • High (1.5M to 10M population)
  • Very high (> 10M population)

Plotting

To keep the map readable, we will limit the number of cities shown for each country based on its size. Larger countries will show more cities, while smaller countries will show fewer

Show the code 
# Auxiliary dataset
country_data <- sf.world %>%
  st_drop_geometry() %>% 
  select(country, area_km2) # Keep only what we need

# Filtering cities based on Country Size
sf.cities.plot <- sf.cities %>%
  # Join the area data to the cities
  left_join(country_data, by = "country") %>%
  
  # Define the "City Limit" rules
  mutate(
    max_cities = case_when(
      area_km2 < 20000   ~ 1,
      area_km2 < 100000  ~ 3,
      area_km2 < 350000  ~ 6, 
      area_km2 < 1000000 ~ 10,
      area_km2 < 5000000 ~ 15,
      TRUE               ~ 25
    )
  ) %>%
  
  # Applying the filter
  group_by(country) %>%
  arrange(desc(pop)) %>%                # Sort largest to smallest
  filter(row_number() <= max_cities) %>% # Keep only the allowed amount
  ungroup()

# Use data set sf.data
# Compute distance between cities and ports and airports by country
# Combine ports and airports
library(units)
sf.transport <- sf.data %>% filter(type %in% c('PORT', 'AIRPORT'))
sf.locations <- sf.data %>% filter(type == 'CITY')

# Calculate distance matrix to all transport hubs
distance_matrix <- st_distance(sf.locations$geom, sf.transport$geom)

# Get minimum distance for each city
sf.locations <- sf.locations %>%
  mutate(
    distance_to_nearest = apply(distance_matrix, 1, min),

# Calculate country-level averages
country_distances <- sf.locations %>%
  st_drop_geometry() %>%
  group_by(country, continent) %>%
  summarize(avg_distance_km = mean(distance_km, na.rm = TRUE),

  filter(!is.na(continent))

From the plots above using the log transformation, several insights can be highlighted. Africa shows higher average distances between cities and transport hubs compared to Europe, which may reflect less developed infrastructure, greater geographic dispersion of cities, or the continent’s larger land area. Europe and North America present similar distributions, with most countries clustered at lower average distances, suggesting well-developed and accessible transport networks.

South America shows less variability in average distances than Africa but centers around similar mean values, indicating moderate transport accessibility with less inter-country variation. Oceania, with fewer countries, exhibits high variability in average distances, likely due to the diverse geographic characteristics of island nations versus continental Australia. Asia displays the widest distribution, with many countries showing high average distances, potentially reflecting the continent’s vast size, varied development levels, and geographic diversity.

airports<-st_read("Data/ne_10m_airports/ne_10m_airports.shp", quiet = TRUE)
airports_africa  <- st_intersection(airports, africa)

For the Africa roads layer, we apply two filters. First, we keep only roads with LENGTH_KM >= 20 so that smaller roads are not considered. We choose this for a couple of reasons; first, because computationally it is very expensive to compute intersections and distances for over 500k+ road observations, so reducing the size of this dataset is beneficial to the efficiency of our task execution; second, because this is a much more relevant analysis of the data – we care more about the distance a market has to a more important, well-connected road than it does to some random neighborhood or back road that may only spans one kilometer and connects to very few homes.

Second, we clip the roads to the Africa polygon (africa_poly) derived from the world dataset, because the roads shapefile also includes features from the Middle East and the southern part of Europe. We use st_intersection() for an exact spatial clip to Africa and we apply the same concept to the coastline data and the airports data.

Computing the distances

To compute the minimum distance:

Show the code 
# Nearest feature index for each market
idx_coast   <- st_nearest_feature(mkt_pts, coastline_africa)
idx_road    <- st_nearest_feature(mkt_pts, africa_roads_clean)
idx_airport <- st_nearest_feature(mkt_pts, airports_africa)

We want the minimum distance for each market individually and we want to compute it efficiently and correctly, without building a huge distance matrix or mixing markets together, st_nearest_feature() tells us which feature is the closest one to each market.

Then we compute the distance only to that feature:

Show the code 
# Minimum distance (meters) to the nearest feature (by element)
d_coast_m <- st_distance(mkt_pts, coastline_africa[idx_coast, ], by_element = TRUE)
d_road_m  <- st_distance(mkt_pts, africa_roads_clean[idx_road, ],      by_element = TRUE)
d_air_m   <- st_distance(mkt_pts, airports_africa[idx_airport,], by_element = TRUE)

# Attach to the markets table (convert to numeric km)
mkt_pts <- mkt_pts %>%
  mutate(
    dist_coast_km   = as.numeric(d_coast_m) / 1000,
    dist_road_km    = as.numeric(d_road_m)  / 1000,
    dist_airport_km = as.numeric(d_air_m)   / 1000
  )

For each market location, we compute the minimum Euclidean distance to the three types of spatial infrastructure: the coastline, the road network, and the nearest airport. This is done using the st_distance() function.

Before computing distances, each market is matched to its nearest feature of the relevant type (coast, road, or airport). Using these matches, st_distance() is applied with the option by_element = TRUE, which ensures that distances are calculated pairwise, which makes that each market is compared only to its own nearest feature rather than to all features in the dataset. As a result, the output is a vector of minimum distances, one value per market, expressed in meters, which correspond to the coordinate reference system of the spatial data.

The resulting distance vectors are then added to the markets dataset as new variables. Distances are converted from meters to kilometers by dividing by 1,000 and stored in three different variables: distance to the coast, distance to the nearest road, and distance to the nearest airport.
